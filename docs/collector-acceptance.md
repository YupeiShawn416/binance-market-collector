# v0.4 采集器验收

本次验收检查常驻入口能否完成接收、持久化、行情发布和故障恢复。先使用自动化故障测试检查处理规则，再用币安实时样本比较采集端、两个消费者和历史回放的结果。

日期：2026-10-16，版本 v0.4。数据流和组件职责见[项目说明](../README.md)，事件含义见[行情接口](event-contract.md)。本页记录该版本的短时验收，长期运行与容量在目标设备上另行测量。

## 自动化故障测试

**101项测试通过**，Ruff 代码检查、格式检查和82份 vendor 上游源文件校验通过。固定依赖安装及命令行入口运行成功。

## 实时采集样本

先通过常驻入口录制25秒：收到335个 WebSocket 帧，生成343个统一事件，待解析原始消息数 `pending_raw=0`。

再录制30秒并启动两个参考消费者。两端各自保存游标和盘口检查点，其中一端在事件序号25退出后重启；采集过程主动触发一次重连，录制结束后运行完整历史回放。

|检查|结果|
|---|---|
|WebSocket 帧 / 全部原始记录|1028 / 1035|
|统一事件|1047|
|Snapshot 快照 / Delta 盘口更新 / Trade 成交|2 / 268 / 759|
|强制重连|1次，新盘口重建代次与快照桥接成功|
|采集端 / 两消费者逐事件与盘口哈希|一致|
|消费者在 seq=25 退出后恢复|与持续消费的一端一致|
|完整历史回放|与采集端一致|

全部原始记录包含 WebSocket 帧、REST 响应和控制记录；一条原始记录可生成多个统一事件。三类计数分别记录接收量、原始证据量和下游事件量。

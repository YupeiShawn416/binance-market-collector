# 数据质量预览

预览工具把已采集的盘口、成交和质量状态放在同一时间轴上，便于检查深度变化、断线位置和数据覆盖范围。输入是行情日志，输出为交互式 HTML、静态 PNG 和统计 JSON。

工具通过只读事务读取统一行情事件 Event v1，使用消费者 Consumer 校验事件，再由盘口状态对象 Projection 重建每个时刻的可见盘口。事件和状态含义见[行情接口](event-contract.md)。HTML 由 Plotly 生成，PNG 由 Matplotlib 的 Agg 渲染器生成。

## 生成预览

先运行采集器，准备 `data/btc.sqlite`，再在项目目录执行：

```bash
uv sync --frozen --extra preview
uv run market-service preview --db data/btc.sqlite --output data/quality-001.html --png data/quality-001.png --report data/quality-001.json
```

HTML 支持悬停、缩放、图例和图片导出；PNG 适合直接查看或放入 README；JSON 保存计数、参数和哈希。输出使用新文件，并与源库及 SQLite 的 `-wal`、`-shm` 辅助文件分离。

|参数|默认值|含义|
|---|---:|---|
|`--max-events`|20000|从日志尾部读取的事件数，上限100000|
|`--time-bin-ms`|100|图中基础时间格宽，长窗口自动取整数倍|
|`--max-time-bins`|600|时间轴最多显示的列数|
|`--price-bins`|120|价格轴格数，边界对齐整数最小价格单位 tick|
|`--band-bps`|20|窗口盘口中位价上下各保留的价格范围，1bps=0.01%|
|`--stale-seconds`|10|盘口过期阈值，应与采集配置一致|

窗口由事件数量决定，实际时长随成交活跃度变化。页面和 JSON 显示实际格宽。图的100ms格宽属于显示参数，采集频率由交易所数据流决定。

活动库通过一次只读 WAL 事务固定读取位置，使统计使用同一份已提交数据。长读取会延迟 WAL 文件回收，大库可先通过 `backup` 生成快照再预览，命令见[部署文档](deployment.md)。

## 图层与计算口径

每个热力格对应一个时间区间和价格区间。盘口深度表示该格中可见挂单量的时间加权均值。例如一格内20ms保持10 BTC、80ms保持2 BTC，显示深度为3.6 BTC。

|图层|计算与显示|
|---|---|
|盘口热力图|按基础币数量计算时间加权深度；颜色为 log(1+数量)，色条和悬停显示实际数量|
|灰色单元|该格存在无效、过期、同步中、部分缺失或快照范围外的时段，数量按未知处理|
|有效覆盖内的零量|使用最低色阶，表示该价格区间的可见挂单量为0|
|最优报价|在完整有效的时间格中显示末次已知买卖报价|
|质量条|分别显示连接、盘口、成交在格内的最差状态；× 标记瞬时状态边界|
|成交量|主动买入和主动卖出的观察成交量按时间格求和，以非负堆叠显示|

主动买入指买方发起并吃掉卖盘的成交，主动卖出对应卖方发起的成交。盘口深度表达挂单存量，成交量表达时间格内已经发生的交易数量。

LIVE（可用）、SYNCING（同步中）、INVALID（失效）、DISCONNECTED（连接结束）来自日志事件。STALE（过期）和 PARTIAL（部分覆盖）由绘图工具计算。盘口年龄取当前时刻与最后一条 Snapshot / Delta 原始接收时间之差；窗口前的数据通过检查点附近的有界查找恢复时间基准，缺失时保留未知。

## 时间顺序与校验范围

横轴使用规范化时间，即服务生成统一事件时的 UTC 墙钟。处理顺序按事件序号 `market_seq` 固定；墙钟回退时，显示坐标保持单调，并在报告中记录调整次数。

预览从窗口前最近的检查点恢复状态。检查点保存此前已计算的盘口和序号，因此工具可以直接继续计算窗口内的数据。校验包括：

- 检查点的校验和、数据集身份和盘口哈希；
- 检查点之后至窗口末尾的事件链与逐事件盘口哈希；
- 窗口事件引用的原始消息校验和。

整库校验通过 `verify` 执行。图中缺失成交 ID 数来自窗口内显式的 `trade_id_gap` 事件；盘口覆盖来自快照的已知价格边界，跨越边界的价格格显示为未知。事后回补成交由独立的 `repaired` 研究视图查询，详见[成交回补](trade-repair.md)。

## 样本与验证结果

2026-10-17 使用采集验收样本生成预览：1047个事件、759笔观察成交、2次快照、268批深度更新、10个缺失成交 ID。有效盘口时长约91.1%，末事件链与盘口哈希匹配[采集验收](collector-acceptance.md)。

测试覆盖时间加权、零量与未知、部分覆盖、断线、过期、检查点、瞬时缺口、墙钟回退、输入损坏及路径保护。PNG 已人工检查；HTML 结构和离线脚本已检查，浏览器交互与窄屏布局列入后续验证。

`preview` 可选依赖由 `uv.lock` 固定。生成文件保存在本地 `data/`；随仓库发布的 README 样例图位于 `docs/assets/`。
